사용자가 적은 요청이 결과에 반영되지 않아 정반대 추천이 나가고 있었다.
"고기 제외한 소주안주"를 적었는데 고깃집·닭갈비가, "AS기사"를 적었는데
정장 재킷이 추천됐다.

음식 카테고리가 AI를 호출하지 않던 문제
- 음식은 위치 기반 Google Places만 시도하고, 실패하면 시나리오별 정적 목록을
  그대로 내보내고 있었다. 그 경로에는 사용자가 적은 요청이 닿을 곳이 없어
  "고기 제외"가 통째로 무시됐다.
- 주변 매장 데이터가 없을 때 AI로 메뉴 후보를 만들도록 바꾸고, 결과를 지도
  검색 카드로 변환한다. 요청 문구를 근거 항목에도 함께 남긴다.

요청을 절대 제약으로 승격
- 프롬프트 맨 앞에 사용자 요청을 두고 다른 조건보다 우선하도록 명시한다.
- "제외/빼고/말고" 같은 부정 표현을 먼저 찾아 해당 대상을 후보에서 전면
  배제하게 하고, 4개를 만든 뒤 스스로 재검토하도록 지시한다.
- 요청에 담긴 직업·장소·용도 맥락을 해석하도록 예시를 준다. AS기사면 이동과
  쪼그려 앉는 작업이 핵심이라 정장 계열은 제외되어야 한다.
- 검색 첫 화면에 나오는 뻔한 답을 금지하고, 그 상황에 실제로 필요하지만
  본인은 떠올리지 못한 후보를 최소 하나 포함하게 한다.

그래프를 종합 점수 하나로
- 축별로 막대를 나눠 그리니 축마다 1등이 달라져 결정을 더 어렵게 만들었다.
  판단을 하나로 좁히는 것이 이 서비스의 역할이므로 종합 적합도 단일 그래프로
  바꾸고 1위를 명시한다.
- 세부 축은 각 후보 카드 안에 작은 보조 지표로 옮긴다.

+export async function searchCoupangProduct(
+  keyword: string,
+  maxPriceWon?: number
+): Promise<CoupangProduct | null> {
+  const normalizedKeyword = normalizeCoupangKeyword(keyword);
+  if (!normalizedKeyword) return null;
+
+  const cacheKey = `${normalizedKeyword}|${maxPriceWon ?? ""}`;
+  const cached = productCache.get(cacheKey);
+  if (cached && cached.expiresAt > Date.now()) return cached.product;
+  if (productCache.size > PRODUCT_CACHE_MAX) {
+    const now = Date.now();
+    productCache.forEach((entry, key) => {
+      if (entry.expiresAt <= now) productCache.delete(key);
+    });
+  }
+
+  let config: CoupangConfig;
+  try {

+  } catch {

+  const authorization = createCoupangAuthorization({

+    accessKey: config.accessKey,
+    secretKey: config.secretKey,
+  });

+  const timeout = setTimeout(() => controller.abort(), DEFAULT_TIMEOUT_MS);
+  try {

+        cache: "no-store",

+      }
