카드 제목과 링크되는 상품이 서로 다른 물건이었다. 실제로 나간 화면에서
"삼성전자 비스포크 제트 스테이션"이라고 띄우고 168,000원짜리 무명 스틱
청소기로 링크가 나갔다. "샤오미 로보락"처럼 서로 다른 회사를 붙인 이름도
있었다. 그런 제품은 없다.

원인은 두 곳이었다.
- 프롬프트가 "널리 팔리는 브랜드가 명확하면 브랜드를 앞에 붙여도 된다"고
  허용하고 있었다. AI 는 이 시점에 어떤 상품이 링크될지 모른다.
- searchCoupangProduct 는 예산 안에 드는 첫 결과를 그대로 집는다. 그것이
  AI 가 의도한 제품인지 확인하지 않는다.

브랜드를 없애는 것은 답이 아니다. 브랜드가 보여야 어떤 물건인지 감이 온다.
그래서 지우는 대신 검증한다.

- brand-verify.ts 를 추가했다. AI 가 붙인 브랜드가 실제 상품명에도 있으면
  그 이름을 그대로 쓰고, 없으면 버리고 실제 상품명에서 만들어 쓴다.
  화면에 뜨는 브랜드는 언제나 실제 판매 상품의 브랜드가 된다.
- 서로 다른 회사가 한 이름에 둘 이상 들어가면 무조건 막는다.
- 표기가 갈리는 브랜드는 별칭으로 묶었다. Dyson·다이슨, Xiaomi·샤오미,
  LG·엘지·코드제로를 같은 브랜드로 본다.
- 쿠팡 상품명은 광고 수식어와 옵션이 길게 붙어 그대로 쓸 수 없다.
  걷어내고 단어 경계에서 잘라 제목으로 쓴다.
- 프롬프트에서 브랜드 허용 문구를 빼고, 제품 종류로 쓰도록 바꿨다.
  실제 브랜드는 상품을 찾은 뒤 그 상품명에서 가져온다.

실제로 나갔던 두 사례를 테스트로 고정했다.

A/B 비교는 사용자가 직접 적은 이름을 쓰므로 같은 문제가 없다.

+function normalize(value: string): string {
+  return value.toLowerCase().replace(/[\s\-_·・,()[\]/]/g, "");
+}

+/** 텍스트에 등장하는 브랜드를 대표 이름으로 모아 돌려준다. */
+export function extractBrands(text: string): string[] {
+  const haystack = normalize(text);
+  const found: string[] = [];
+
+  for (const aliases of BRAND_ALIASES) {
+    const hit = aliases.some((alias) => haystack.includes(normalize(alias)));
+    if (hit) found.push(aliases[0]);
+  }
+  return found;
+}

+export function cleanProductName(productName: string, maxLength = 34): string {
+  let cleaned = productName

+    .split(/[,/|]|＋|\+/)[0]

+    .trim();

+  if (cleaned.length > maxLength) {

+    const cut = cleaned.slice(0, maxLength);
+    const lastSpace = cut.lastIndexOf(" ");
+    cleaned = (lastSpace > maxLength * 0.6 ? cut.slice(0, lastSpace) : cut).trim();
+  }

+export type NameCheck =
+  | { ok: true }
+  | { ok: false; reason: "multiple-brands" | "brand-not-in-product" };

+/**
+ * AI 가 지은 이름을 그대로 써도 되는지 본다.
+ *
+ * 막는 것은 두 가지다.
+ * - 한 이름에 서로 다른 브랜드가 둘 이상 (예: "샤오미 로보락"). 그런 제품은 없다.
+ * - 실제 상품에 없는 브랜드 (예: 무명 스틱청소기를 "삼성전자"로 표기).
+ */
+export function checkNameAgainstProduct(
+  aiName: string,
+  productName: string
+): NameCheck {
+  const nameBrands = extractBrands(aiName);
+  if (nameBrands.length === 0) return { ok: true };
+  if (nameBrands.length > 1) return { ok: false, reason: "multiple-brands" };
+
+  const productBrands = extractBrands(productName);
+  return productBrands.includes(nameBrands[0])
+    ? { ok: true }
+    : { ok: false, reason: "brand-not-in-product" };
+}

+/**
+ * 화면에 띄울 이름을 정한다.
+ * 검증을 통과하면 AI 이름을, 아니면 실제 상품명을 정리해 쓴다.
+ */
+export function resolveDisplayName(
+  aiName: string,
+  productName: string | undefined
+): string {
+  const trimmedAi = aiName.trim();
+  if (!productName?.trim()) return trimmedAi;
+
+  return checkNameAgainstProduct(trimmedAi, productName).ok
+    ? trimmedAi
+    : cleanProductName(productName);
+}

같은 조건으로 다시 추천받으면 매번 다른 후보가 나왔다. 원인은 두 가지였다.

- 최근 추천한 이름을 프롬프트에 넣어 "반드시 제외"시키고 있었다.
- 생성 온도를 지정하지 않아 기본값(높은 쪽)으로 돌고 있었다.

버튼만 눌러 들어온 요청이면 새로운 후보를 보여주는 편이 낫다. 아직
둘러보는 중이기 때문이다. 하지만 원하는 것을 직접 적었다면 이야기가
다르다. "먼지통 자동으로 비워지는 걸로"라고 쓴 사람에게 잘 맞는 답은
하나로 좁혀진다. 이미 봤다는 이유로 그 답을 빼면 다음 번에 더 나쁜 후보가
올라온다. 새로움이 정확도를 밀어내는 셈이다.

그래서 자유 입력이 있을 때만 다르게 동작하게 했다.
- 최근 추천 제외를 적용하지 않는다.
- 생성 온도를 0.2 로 낮춰 같은 요청에 같은 답이 나올 확률을 높인다.

generateJson 에 temperature 를 넘길 수 있게 했다. 일부 최신 OpenAI 모델은
temperature 를 아예 받지 않고 요청을 거부하므로, 거부당하면 온도 없이 한 번
더 시도한다. 답이 조금 흔들리더라도 provider 가 통째로 실패해 정적 폴백으로
떨어지는 것보다 낫다.
